# 干员培养推荐（按挂机作业出现率）

> **别名 / 用户口中的说法（搜这些词都命中本 skill）**：
> 「**干员培养优先级表**」「**战斗方向的培养倾向表**」「战斗向培养」「抄作业最高频的干员」
> 「要养谁」「还有谁要练」「练度对照」「培养倾向」。
> **产物 = `scheduling/tools/oper_appearance.json`**（用户说的「那张表」就是它）。
> 用户一提这张表 → **先读这个 json**，别再满仓库找。

脚本：`scheduling/tools/oper_appearance.py`；产出 `scheduling/tools/oper_appearance.json`。

## 产物结构
`{sample, kw, order, opers:[{name, required_count, required_rate, group_count, status}]}`
- `status`：`缺`(没抽到) / `E0` / `E1` / `E2`。**「要养」= status ∈ {E0,E1}**；按 `required_rate` 降序 = **培养优先级**。
- 快照(2026-10-10, 1500 挂机作业)：E2=40、E0=54、E1=26、缺=43。
  高频要养：德克萨斯27%、乌尔比安23%、伊芙利特14%、山12%、夜莺12%、拉普兰德8.6%、澄闪7.4%。

## 下游：从「培养优先级」推到「每天打什么」——固定顺序（**别跳步**）
> 踩过的坑：先看**库存**→推"刷 YW-8"，被**需求**推翻（液化高能气体：80 个要养干员里 **0 人用**）。
> **铁律：先算需求 D → 再看库存 S → 缺口 G=D−S → 最后才挑供给（刷关 / 商店 / 常规图）性价比。**

1. **定目标集 = 基建刚需 ∪ 抄作业刚需**（**不是只看抄作业出现率**）：
   - **基建刚需**：`report_data.json.advice` / `training.json` 里 ★推荐 的干员（为基建技能精二，如 阿罗玛/贝洛内/苍苔/但书…）。
   - **抄作业刚需**：`oper_appearance.json` 里高频且 `status ∈ {E0,E1}` 的（如 德克萨斯27%、乌尔比安23%、伊芙利特14%、山12%、夜莺12%、拉普兰德8.6%、澄闪7.4%…）。
   - **别全都养**：取并集后再按「出现率/推荐度」截前 N（用户明确：不养那么多）。
2. **算需求 D —— 大头是「专精 + 模组」，不是全员精二**：
   - **技能专精（权重最高）**：**常用干员**的常用技能 → `character_table.json` `skills[].levelUpCostCond`（专一~专三）。
   - **模组升级（权重次高）**：**常用干员**的模组 → `uniequip_table.json` / `battle_equip_table.json`（1/2/3 级）。
   - **精英化**：只给「目标集里还没精二」的那些算 → `phases[1|2].evolveCost`（E0 走 1+2 段，E1 只 2 段）。
   - **统计每个材料的「需求量」与「用人数」**——用人数少的料，需求再低也别刷。
3. **合成路径折算**：`item_table.json` 配方把高/低阶并到同一基准（缺「改量装置」→ 可用「全新装置」补；
   缺「转质盐聚块」→ 可用「转质盐组」补）。**别只看裸数量**。
4. **减库存 S**：`C:\MAA\data\DepotData.json`（`data={itemId:数量}`，id 与官方/企鹅一致）→ 缺口 G。
5. **挑供给（按 G 排序后逐项比性价比）**：
   - **当期活动**：代币 = 理智 **1:1 三星**（各关相同）→ 代币价值在**商店**；关卡掉落**必须先看该料的用人数**。
   - **商店**：把料按「需求 G ÷ 代币价」排序 → 先换最缺且最便宜的高需求料（如 技巧概要·卷3 4代币/限25）。
   - **常规图**：企鹅物流 `quantity/times ÷ 理智` = 每理智产出；需求大且活动/商店覆盖不到的才去常规图刷。
6. **套约束**：每日理智 ≈274（自然240+周常摊34）−剿灭18；**搓玉的固源岩下限**（用户要求库存 ≥1000）；
   活动期限/兑换截止。 → 输出「每天打什么 + 代币怎么花」。
7. 相关：`docs/WORKFLOW-活动关作业.md`、skill `arknights-event-economy`、`docs/DATA-SOURCES.md`。

## 思路
「出现率高」= 以后各关都能抄到 → 练它收益最大。所以从作业站抓大量**挂机作业**，统计每个干员出现频率，再和本人干员箱对照。

## 用法
```bash
python scheduling/tools/oper_appearance.py --pages 15 --top 25
# 产出 oper_appearance.json + 控制台排行（含"建议培养/缺"）
```

## 数据来源与口径
- 作业站 `https://prts.maa.plus/copilot/query`：
  - **`document=挂机`** 按标题/详情筛挂机作业（共约 1.2 万）；
  - `orderBy=views`（热门）/`hot`（近期热度）；
  - `limit=100` + `page` 翻页（每页 100，无需 `/copilot/get`，列表 content 已含 opers）。
- 出现率 = 该干员(作业**顶层必选** opers)出现次数 / 样本作业数；替选组(groups)成员单独统计。
- 对照 `C:\MAA\data\OperBoxData.json`：owned-not-E2 = 培养目标；缺 = 无法练。
  > 干员箱可换**在线源**（免模拟器，无需开雷电）：`ark_operbox_online`（MCP）或
  > `scripts/skland/skland_box.py` 的 `fetch_operbox()`，形态与 `OperBoxData.json` 同构。

## 实测结论（2026-10-09，1500 个热门挂机作业）
- 必选高频：煌34.5%、艾雅法拉33.1%、德克萨斯27%、乌尔比安23%、歌蕾蒂娅23%、塞雷娅22%、圣聆初雪19%…
- **建议精二**（我 owned 但未 E2）：德克萨斯、乌尔比安、伊芙利特、山、夜莺、拉普兰德、澄闪…
- **缺但高频**（值得抽/借）：煌、艾雅法拉、纯烬艾雅法拉、阿斯卡纶、黍…

## 注意
- 只看"挂机"会让结果偏"摆完挂机/低操作"取向；要泛用可去掉 `--kw`（全量 4 万+，样本更大更慢）。
- 当前活动的新作业会拉高"近期热度"；按 `views` 更能反映"长期出现率"。
