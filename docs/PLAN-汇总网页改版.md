# 汇总网页改版规划（`scheduling/报告/汇总.html`）

> 目标：把汇总网页从「**设计文档 + 数据 dump**」改造成「**今天的决策看板**」——
> 一眼看**今天做什么**、二眼看**本周进度**、需要才看**培养/公招**。
> 范围：**只动网页本身**（`scheduling/tools/build_site.py` 的 section 组合 / 文案 / 布局）；
> 不涉及数据采集与定时刷新口径。

## 2. 问题（对照"用户使用逻辑"）

用户的日常循环是：每日 14:00 自动跑日常 → **偶尔上线 1 次、花光理智**。打开网页最想知道的是：

1. **今天该刷什么关、各几次、大概多少理智、要不要吃药**（最高频）；
2. **本周还差多少 / 各关进度**；
3. **活动**：开放窗口剩几天、EX/S 何时开、要刷多少；
4. **培养**：目标干员还差什么、还需多少理智/几周；
5. 偶发：**公招**（刷出好词条才查）。

现状与这些诉求的错位：

- ❌ **没有"今天"**：首页是 4 张抽象卡，用户第一眼看不到"今天刷什么"。
- ❌ **最大的页面是设计文档**（一键长草 17k），与日常使用无关且会过时。
- ❌ **两个死页**（周报空、排班旧），占导航、误导点击。
- ⚠ **重复**：概览「本周/理智」卡 ↔ 本周页；理智药出现在概览卡 + 本周表两处。
- ⚠ **一页塞太多**（本周页）：tasks/逐日/上线建议/培养/脚本/药混排，重点被淹没。
- ⚠ **公招工具**要本地起 `site_server.py` 才可用，却放在默认首页；日常无价值，且与桌面 GUI 的「公招」页重复。

## 3. 设计原则

1. **今天优先**：默认页 = 今天要做什么（一张可执行清单）。
2. **一屏一问**：每页回答一个问题（今天 / 本周 / 培养）。
3. **去文档化**：网页只放**结论与可执行项**，设计/原理留在 `docs/`。
4. **不重复**：同一数字只出现一次。
5. **宁删勿留**：过时/空壳页直接下架（代码保留便于回归）。

## 4. 改版方案（Tab 5 → 3）

### 4.1 新增 / 改造

| 页 | 内容 | 数据 |
|---|---|---|
| **① 今天**（默认首页） | 顶部**状态条**：日期/星期 · 页面更新 · 计划生成 · 当前理智/药<br>**今天要刷**：表（关卡 × 次数 × 单次理智 × 小计；连战批次；是否吃药；预计跑完理智）<br>**今日提示**：活动窗口剩余天数、今天新开的关、缺理智/超上限提醒、**计划 stale 醒目提示** | `weekly_plan.daily[今天]` + `tasks` |
| **② 本周** | 逐日安排表（**今天高亮**、超上限标红）<br>预算条：自然 + 药 → 已排/剩余<br>各关进度（剿灭 x/5、活动、1-7）<br>理智药存量（**唯一一处**） | `weekly_plan` + `sanity.json` |

### 4.2 下架 / 合并

| 原页 | 处置 | 理由 |
|---|---|---|
| **一键长草** | **删** | 是设计文档，不是用户内容；想看直接开 `docs/PLAN-一键长草.md` |
| **排班** | **删** | 自研排班已归档，基建交 MAA 自定义换班（Custom）；`index.html` 过时 |

| **公招工具** | 从首页**移到「培养/工具」页** | 偶发使用、依赖后端，不该占默认页 |

### 4.3 保留并增强

- 「今天」表**直接从 `weekly_plan.daily` 取当天那一行**（计划已产出逐日视图，无需重算）。
- 逐日表**今天整行高亮**，「★本日新开」保留。
- **计划 stale 提示**：复用 `plan_util.plan_day(plan, today)`，非 `ok` 时在首页顶部红字提示
  （「计划未覆盖今天/已过期 → 重生成 `plan_week.py`」），避免"用了旧账还不自知"。
- 公招工具保留「边输边算」的 JS，但**移到工具页**后才注入 DOM id。

## 5. `build_site.py` 改动清单

- **删函数/调用**：`rotation_section()`、`weekly_report_section()` 的渲染、`plan_html`（`render_markdown(PLAN_MD)`）
  及其数据读取（`ledger`、`run_report` 可保留给 `build_alert`，或一并简化）。
- **新增**：`today_section(plan, sanity)`——取 `<today>` 的 daily 行 + 该日 runs 明细 + 提示。
- **改造**：`overview_section` → 拆出 `status_bar(plan, sanity)`（并入 today）；
  `weekly_section` → 精简（逐日 + 预算条 + 各关进度 + 药表），移除「上线建议」长说明或折叠；
  `recruit_block` + `RECRUIT_TOOL` → 归入工具页。
- **导航**：`nav` 三项（今天/本周/培养·工具）；`build()` 的 `body` 组合同步。
- **CSS**：加状态条样式、今日高亮 `tr.today`；其余沿用。
- **时间戳**：保留「计划生成 / 页面更新」；stale 时高亮。

## 7. 取舍与风险

- **删「一键长草」**：少一个"网页自带文档"，但文档仍在 `docs/`，且 GUI/README 有入口；收益是页面瘦身一半以上。
- **删「排班」**：需确认 `index.html` 确无其它消费方（目前仅此 iframe 引用）。
- **删「周报」**：函数保留、仅不渲染，数据接好可一键回归。
- **公招工具后置**：不影响主流程；依赖 `site_server.py` 的说明保留在工具页。

## 8. 验收标准

1. 默认打开即见**今天要刷的关与次数**（无需切换 tab）。
2. 全站 tab ≤ 3；无空页、无文档页、无 iframe 旧报告。
3. 同一数字（理智/药）不再两处重复；计划 stale 时首页有醒目提示。
4. 生成命令不变：`python scheduling/tools/build_site.py`。
