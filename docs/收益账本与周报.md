# 收益账本与周报

> 把「玩方舟」的**每日收支 + 练度变化**记成可聚合账本，自动出周报（练度提升 / 踩坑 / 下周优化）。
> 账本只记**差额**（前后对比），不存全量快照（`docs/STATE.md §7`）。工具：`scheduling/tools/revenue_ledger.py`（记账）、`revenue_weekly.py`（聚合渲染）。

## 一、账本文件

`scheduling/data/revenue_ledger.jsonl`，追加式，**一行 = 一个 04:00 结算段**。主要字段：
`schema / window{start,end} / ts / base / farm / spend / train[] / predict / actual / delta / issues[] / note`。
`base`=基建收益，`farm`=刷关所得，`spend`=消耗，`train[]`=练度变化 `{name,field,from,to}`（`field∈ elite/level/skill_N/spec_N/mod_N/new`）。

## 二、设备采集接口 bundle.json（定稿）

设备侧 agent 每结算段产出一个 **bundle.json**（原始快照只落 `%TEMP%\opencode\ark\bundle-last.json`，**不入库**），交给逻辑差分。
**归属**：`设备侧`=采集方必填/选填；`脚本自动`=工具差分产出（不写进 bundle）。**级别**：必需 / 可选 / 自动。

| 字段 | 归属 | 级别 | 口径 / 来源 |
|---|---|---|---|
| `ts` | 设备侧 | 必需 | 落账时刻 ISO，如 `2026-10-10T04:05` |
| `sanity` | 设备侧 | 必需 | **实机理智截图**读数（森空岛 ap 不可信） |
| `depot` | 设备侧 | 必需 | `{物品名\|itemId: 数量}`，MAA `DepotData.json` |
| `operbox` | 设备侧 | 必需 | 森空岛 `ark_operbox_online` 快照数组（练度差分用） |
| `window_start` / `window_end` | 设备侧 | 可选 | 结算窗；缺则按 `ts` 推导（当日 04:00） |
| `sanity_spent` | 设备侧 | 可选 | 权威理智消耗；缺则按 10/h + 理智药估算 |
| `meds` | 设备侧 | 可选 | `{理智药名: 存量}`，**仓库页 OCR** |
| `depot_names` | 设备侧 | 可选 | `{itemId: 中文名}`，`depot` 用 itemId 时必给 |
| `tokens` | 设备侧 | 可选 | `{actId: 数量}` 活动代币读数 |
| `stage_runs` | 设备侧 | 可选 | `{关卡: 次数}` 本段运行的关 |
| `secondary_brief` | 设备侧 | 可选 | `{src,parsed,raw}` 副手简报 OCR（`parsed`=设施→产物量） |
| `plan` | 设备侧 | 可选 | `{理智,活动代币,龙门币}` 计划预期（MASTER-PLAN 判据） |
| `issues[]` / `note` | 设备侧 | 可选 | 踩坑项 / 备注（也可命令行 `--issue/--note`） |
| `base` / `farm` / `spend` / `train[]` | **脚本自动** | 自动 | 由上述差分产出，不写进 bundle |
| `predict` / `actual` / `delta` | **脚本自动** | 自动 | `plan` vs 实测（给了 `plan` 才有） |

差分规则（工具负责）：`depot` 差分 → `farm.材料/龙门币` + `spend.材料/龙门币`；`operbox` → `train[]`；`tokens` → `farm.活动代币`；`sanity/meds` → `spend.理智`；`plan` vs 实测 → `delta`。
**数据来源映射**：基建收益=游戏内「控制中枢→基建副手→副手简报」截图 OCR；刷关材料/龙门币/固源岩=`DepotData.json` 前后差分；理智=实机截图；理智药=仓库页 OCR；练度=森空岛两次快照差分。
**省 token 原则**：只记「物品差额」；原始快照/OCR 原文只在 `%TEMP%` 留证，不进账本、不进对话。

> 模板与校验：`revenue_ledger.py bundle`（产出含 `_fields` 归属标注的模板）；`revenue_ledger.py validate --bundle <b>`（缺必需字段即报错）。

## 三、周报三块模板

1. **本周练度提升**：`train[]` 按「干员+字段」折叠成净变化（精一→精二 / Lv / 技能 / 专精 / 模组），并分类计数。
2. **本周踩坑**：各行 `issues[]` 汇总清单。
3. **下周优化**：启发式——理智去向（对比 1920/周预算）、龙门币净额→CE-6、固源岩缺口→1-7、活动代币→商店优先级、练度零提升则提示补刚需。

HTML 复用 `render_report.py` 的 `e()` 与内联 Pico.css（`%TEMP%\opencode\pico.min.css`）。

## 四、运行

```powershell
# 账本
python scheduling/tools/revenue_ledger.py collect                                  # ★自动采集 bundle（MAA仓库+森空岛干员箱+理智读数+当日计划）
python scheduling/tools/revenue_ledger.py settle --auto [--issue X] [--note ..]    # ★自动采集并差分追加一行（首次=基线）
python scheduling/tools/revenue_ledger.py bundle                                   # 写 bundle 模板（人工采集用，含归属标注）
python scheduling/tools/revenue_ledger.py validate --bundle b.json                 # 校验采集包
python scheduling/tools/revenue_ledger.py settle --bundle b.json [--issue X]       # 人工包差分并追加一行
python scheduling/tools/revenue_ledger.py show                                     # 账本概况
# 周报 / 看板
python scheduling/tools/build_site.py                                              # 汇总网页（「账本」页读 revenue_ledger.jsonl）
python scheduling/tools/revenue_weekly.py demo                                     # 周报假数据演示
python scheduling/tools/revenue_weekly.py --in scheduling/data/revenue_ledger.jsonl [--days 7]
```

> **自动采集来源**（`collect` / `settle --auto`）：`depot`←MAA `DepotData.json`(+`item_index` 名)、
> `operbox`←森空岛 `ark_operbox_online`（含技能/专精/模组，退回 MAA `OperBoxData.json`）、
> `sanity`←`scheduling/data/sanity.json` 的 `current_sanity`（实机截图读数）、`plan`←`weekly_plan` 当日 `daily.sanity`。
> 仍缺：`meds`（按名存量）/`tokens`（活动代币）/`stage_runs`/`secondary_brief`（副手简报）—— 属可选字段，缺则对应项留空。
> **结算节奏**：每 04:00 结算段跑一次 `settle --auto` 即得一行；首次为基线（无差额）。

产物：真实周报 `scheduling/报告/周报.html`；演示/中间快照 `%TEMP%\opencode\ark\`（`weekly-demo.html`、`bundle-last.json`）。

## 五、落地阶段

1. **P0（可跑）**：账本读写 + 差分 + bundle 校验/模板 + 周报渲染；假数据端到端已验。
2. **P1（已接，2026-10-14）**：`revenue_ledger.py collect` / `settle --auto` **自动采集本机可得数据源**
   （MAA depot + 森空岛 operbox + 理智读数 + 当日计划）。**仍缺的可选字段**：`meds`（按名存量）、
   `tokens`（活动代币）、`stage_runs`、`secondary_brief`（副手简报 OCR）——补齐后账本更完整。
3. **P2（已接，2026-10-14）**：接入「方舟·每日日常」（`scripts/daily-auto/daily_auto.py`，每天 14:00）——
   当天日常跑成功且非 MAA GUI 忙时：先 `maa_week.py depot`（刷 `DepotData.json`，直驱 MaaCore 自己写文件）
   再 `revenue_ledger.py settle --auto`；两步旁路、失败不影响日常。`daily_run.jsonl` 记 `depot_rc`/`ledger_rc`。
4. **P3**：账本聚合（练度提升/踩坑/下周优化）并入汇总网页「账本」页（现为逐段明细）；周报走 lan `http.server` 手机看。
